# ライフオラクル制作委員会 担当者会議 議事録

**開催日**：2026-06-05
**議題**：① 全体色調変更によるコントラスト崩壊の大規模修繕　② 質問構成が不人気原因という仮説のストレステストと改善
**結論**：両議題とも実装完了・検証済み

---

## 背景

Entry画面を「漆黒×純金（design A）」へリデザインした結果、Entryだけが暗色になり、
それ以降の質問・結果画面は明色（クリーム地）のまま残った。
特に `MbtiEntry` 画面が**暗色テーマ用の選択肢ボタンを明色地で使い回し**、
クリーム色の文字がクリーム地に溶けて読めなくなっていた（実機スクショで確認）。

加えて代表（俊雄）より「4択質問の文字が分散していない／似た選択肢が多い／
回答が度合いでないので選びにくい」という不人気仮説が提示された。

---

## 各責任者の診断と決定事項

### 🎨 アートディレクター（UI/ビジュアル）
**診断**：
- Entryのみ暗色化し、`:root` トークン（`--bg` `--text` `--card-bg` 等）は明色のまま放置。
  コンポーネントの多くが `var(--*)` を参照しているため、トークンを反転すれば一括で暗色化できる。
- `MbtiEntry` の選択肢が `entry-choice-button`（暗色用・文字色 `#e8e0cc`）を流用しており、
  明色地で不可視。これが「文字が見えない」の正体。

**決定・実装**：
- デザイントークンを漆黒×純金へ全面反転（`--bg:#0a0b12` / `--text:#ece4d0` / `--accent:#d4af37` / `--card-bg:rgba(255,255,255,0.04)`）。
- body 背景を金のラジアルグロー＋漆黒に統一。
- ハードコードされていた明色（`#ffffff`系カード・`rgba(45,35,24,...)`オーバーレイ・`#fdf7f7`等）を
  ダークガラス／白オーバーレイ／黒シャドウへ置換。
- 全画面（Entry / MbtiEntry / Quiz / TopicSelect / TargetSelect / PostQuiz / 結果）を実機スクショで検証。

### 🧩 UXデザイナー（操作体験）
**診断**：
- カテゴリ型4択は「4つの似た文章を読み比べて1つ選ぶ」構造で認知負荷が高い。
  選択肢に視覚的な足場（アンカー）がなく、のっぺりして見える＝「文字が分散していない」の体感原因。
- 押下→即画面遷移で、選んだ手応え（歓喜の一拍）がない。

**決定・実装**：
- カテゴリ型4択に**レター・アンカー（A/B/C/D の金リングチップ）**を追加。4択が一目で分離可能に。
- 各選択肢を**段階フェードイン**（0.06s ずつ）で出現させ、リズムを作る。
- 押下時に**金のパルス＋拡大フィードバック（240ms）**を入れてから回答送信。二重押下も防止。
- プログレスバーを金グラデ＋グローに、コールドリーディング枠を金箔調に格上げ。

### 🧠 心理設計監修（診断ロジック）
**診断**：
- MBTIフロー（自分を知る）は既に「そう／わからない／ちがう」の**3段階スケール**で良好。度合い型の見本。
- 状況・攻略フローは各選択肢が別タグ／別jinタイプへマップする**カテゴリ型が必須**。
  純粋なスケール化はスコアリングを壊すため不可。→ 度合い化ではなく**選択肢の対比明確化**で対応する。
- スコア寄与のない中立選択肢（`not_changed` `balanced`）は「どれも当てはまらない人」の逃げ道として**意図的に正当**。

**決定**：
- 度合い型への一律変換はしない（診断健全性を維持）。代わりに似すぎ選択肢を editorial 修正。

### ✍️ コピーライター（質問文）
**診断・実装**：
- `atk_b_002` の2選択肢が「機嫌は安定しているが、…」で語頭重複し見分けづらい
  → 「評価や見方が一度決まると、もう動かない」「言うことや指示が、日によってコロコロ変わる」に書き換え（スコアは保持）。

### 📊 データアナリスト（品質保証）
**診断・実装**：
- 質問構成を機械診断する **QA Lint（`life-oracle-v2/qa_questions.mjs`）** を新規作成。
  検出項目：①意味が似すぎる選択肢ペア（bigram Dice類似度）②全選択肢が同語尾／同語頭 ③無スコア選択肢。
- **ストレステスト3回実施**：
  | 回 | 問題のある質問 |
  |---|---|
  | #1 baseline | 5 |
  | #2 editorial修正後 | 4 |
  | #3 最終 | 4（残りは全て正当：転職回数=度合いスケール／中立選択肢×2／自然な語尾） |
- 結論：207問中、真の欠陥はごく僅か。**不人気の主因はデータ欠陥ではなくUIの認知負荷**だった、という仮説修正に至った。

## 成果サマリ

| 項目 | Before | After |
|---|---|---|
| 全体テーマ | Entryのみ暗色・他は明色（不統一） | 全画面 漆黒×純金で統一 |
| MbtiEntry 可読性 | クリーム文字がクリーム地で不可視 | 暗地で明瞭に可読 |
| カテゴリ型4択 | のっぺり・選びにくい | A/B/C/D アンカー＋段階表示で一目で分離 |
| 押下体験 | 即遷移（手応えなし） | 金パルス→送信（歓喜の一拍） |
| 質問QA | 計測手段なし | QA Lint＋3回ストレステストで継続監視可能 |
