# 委員会 2026-06-09 決定4 — 入口質問「短い動詞」圧縮 Before→After ドラフト

> **状態：ドラフト（適用は俊雄さん判断待ち）。** 委員会2026-06-09 決定4「入口質問の長文4択を『短い動詞1つ』に圧縮するBefore→After案を全カテゴリ横断で1枚に確定（文言のみ・スコア非改変）」の成果物。
> コンテンツ担当の根拠：入口の長文4択（「・」「または」の二重状態）が**離脱とスコアブレの主因**。最初の1問を「サクサク答えられた」体験にすると完走率＝発信の母数に効く。

---

## 圧縮の原則

1. **核となる動詞1語（2〜6字）に寄せる**。観察視点（「その人は〜する」）の主語で読める形。
2. **「・」「または」の二重状態を解消**。1選択肢＝1つの行動に絞る（弁別力の高い方を残し、補足はカッコで最小限）。
3. **スコアは一切触らない**。各選択肢の `id` / `attackTypeHints` / `biasHints` / `jungShadowHints` / `tags` は保持。**変えるのは `label` のみ**（id と行の対応を保てば hints は自動で維持される）。
4. 対象は **attack（相手を知る）9カテゴリの入口質問（`type: 'entry'`）のみ**。self（MBTI 32問・Likert）と situation 系は別フォーマットのため本ドラフト対象外（必要なら次段階）。

## 実装手順（俊雄さん承認後・別タスク）

1. `life-oracle-v2/src/data_v2/questions/attack_*.js` の各 `type: 'entry'` 質問について、選択肢の **`label` のみ** を After 案に置換する。
2. `id` / `*Hints` / `tags` は触らない（スコア非改変＝16タイプ判定・バイアス・ユング軸は不変）。
3. After を採用すると選択肢が短くなりすぎて意味が落ちる場合は、カッコ補足を残す（例：「決めつける（印象を更新しない）」）。最終トーンは俊雄さん判断。
4. 変更後 `npm run build` でビルド確認 → プレビューで attack 入口の表示を1カテゴリ確認。

## 留意点

- After は「動詞中心」だが、観察対象の行動を表すため完全1語にすると断定的になりがち。**離脱低減（速答）と意味保持のバランス**は俊雄さんが最終決定。
- probe（深掘り）質問は対象外。入口の第一印象だけを軽くするのが狙い（深さは結果画面で殴る＝WEEKLY_SPRINT の落差設計）。
- self / situation の入口も同様の課題があれば次段階で。今回は attack に限定。
