# 📊 データ担当 日次レポート — 2026-06-08

## 調査サマリ（今日わかったこと・3〜6点、箇条書き）

- **GA4 が未連携のため、現状すべての行動データが「観測不能」**。完走率も離脱点も結果分布も、今は何ひとつ事実として言えない状態。これ自体が最大のリスク。
- 計測ゼロの今、最初に設置すべき北極星指標は **「診断完走率（開始 → 結果到達）」** だと考える。SNSで噂されるには「最後まで体験して感動した人」の絶対数が必要で、その分母を握る指標だから。
- ただし完走率は「結果」であって「原因」ではない。改善の打ち手に直結するのは **「設問ごとの離脱率（どこで脱落するか）」** で、これが第二優先。
- 第三に **「結果タイプ分布の偏り」**。特定の結果に偏っていると「みんな同じ結果＝シェアされない」という致命傷になりうる。多様性が担保されて初めて「私はこれだった！」という拡散が起きる。
- 計測が無い間に「凄いと言いたくなったか」を測る代理指標として、**結果ページからのシェア/コピー/再訪** を最初からイベント設計に含めておくべき。これが北極星（自然発生的な言及）に最も近いデータ。

## なぜ重要か（理由）

- **完走率**：途中離脱した人は感動も拡散もしない。SNSで噂される母数 = 完走者数 × 感動率。完走率が分母なので、ここを知らずに改善は不可能。
- **設問別離脱率**：完走率が低いとき「なぜ低いか」を答えられるのはここだけ。例えば「Q3で30%脱落」なら、UX担当に「Q3の質問文・選択肢を見て」と具体的に投げられる。集計屋で終わらないための核心データ。
- **結果タイプ分布**：拡散の燃料は「自分だけの結果感」。10種の結果が均等に近いほど「友達と違った！比べたい！」が生まれる。逆に1〜2タイプに集中していると、SNS上で同じ画像が並び、新鮮味＝拡散力が死ぬ。
- **シェア/コピーイベント**：ベンチマークは「他者からの自然発生的言及」。それに最も近いログは結果ページでのシェア行動。完走率より遠いが、北極星を直接照らす唯一の数字なので、計測初日から仕込む価値がある。

## 改善提案（具体・実装可能・優先度つき）

**【優先度：最高】GA4 計測を有効化する（今日着手）**
1. GA4 プロパティを作成 →「データストリーム」でウェブを追加し、**測定ID（G-XXXX）** を取得。
2. GCP でサービスアカウントを作成 → JSON キーを発行（GA4 Data API 用）。
3. GitHub の対象リポジトリ → Settings → Secrets and variables → Actions に以下を登録：
   - `GOOGLE_CREDENTIALS_JSON`（発行したJSONの中身まるごと）
   - `GA4_PROPERTY_ID`（GA4管理画面の「プロパティ設定」にある数値ID。`G-` ではなく数字）
4. GA4 管理 → プロパティアクセス管理で、サービスアカウントのメールを **閲覧者** 権限で追加。
5. 接続後、まず `sessions` と `totalUsers` が取れるかだけ確認（疎通テスト）。

**【優先度：高】イベント設計を最初から仕込む（連携と同時）**
- `diagnosis_start`（診断開始）
- `question_view`（設問ごと、パラメータに `question_no`）← 離脱率算出の生命線
- `diagnosis_complete`（結果到達）
- `result_view`（パラメータに `result_type`）← 分布分析用
- `result_share` / `result_copy`（北極星に最も近い行動）

**【優先度：中】仮の合格ラインを先に決めておく**
- 完走率の暫定目標：**60%以上**（診断系の体感水準）。下回ったら設問別離脱を即調査。
- 結果分布：最多タイプが全体の **25%を超えたら偏りアラート** としてコンテンツ/エンジン担当に共有。

**【優先度：中】計測できるまでの代替**
- 連携完了までの数日は、知人5〜10名に実際に通してもらい「何問目で迷ったか」を口頭ヒアリング。設問別離脱の超ミニ版を手動で取る。
